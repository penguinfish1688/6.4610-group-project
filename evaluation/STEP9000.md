## Why an adapter is needed

AVQA files contain `env_mel`, `self_mel`, text/codec targets, masks and visual
segments. They do not contain input waveforms or raw videos. Each visual segment
records tick bounds, clip duration, 12 vectors per sampled image and three
DeepStack feature banks. The original runner takes waveform-based inputs.

The adapter splits each AVQA conversation at its recorded segment boundaries.
It sends only that segment's environment mel to the existing causal audio
encoder, eight mel frames per 80-ms tick. Generated self-audio still follows the
normal waveform feedback path. Each rollout starts fresh audio/Thinker/Talker
state. Cached mel retains the original concatenated frontend normalization and
boundary context; this is not claimed to be a bit-identical independently
reprocessed waveform protocol. Twelve seconds of silent mel are appended using
the observed causal prefix's dynamic-range floor; no future normalization is used.

Reference text is decoded from supervised text solely for scoring. Teacher
assistant audio/mel, codec targets and text targets are never supplied as
generation feedback. Input PCM placeholders are not rendered or presented as
real input audio. Generated output audio is saved normally.

## Conditions and model comparison

- `finetuned`: checkpoint 9,000 with correct, padding and mismatched vision.
- `base-d2`: original released D2 weights, without enabling the visual lane or
  loading fine-tuned weights. Use only `--conditions padding`; this label means
  no visual input, but the base model has the original three-position layout.

Compare the same selected cases across separate output directories. D2 vs the
fine-tuned model also changes weights/layout, so paired visual ablations within
the fine-tuned model are the cleaner visual-reliance comparison.
